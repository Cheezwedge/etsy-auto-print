# Etsy Auto-Print: Automated Shipping Label Design

Automatically print shipping labels (address + carrier barcode) on a label
printer whenever an Etsy order is placed and paid.

## The one constraint that shapes everything

**Etsy's Open API v3 cannot purchase Etsy shipping labels.** Label purchase is
only available in Etsy's seller UI; the payments/ledger endpoints are
read-only, and Etsy has declined to expose the internal label-purchase
endpoint to third-party apps.

What the API *can* do:

- Tell us when an order is paid — via the `order.paid` **webhook** (now
  available to personal apps) or by polling `getShopReceipts`.
- Give us everything needed to make a label: buyer name, formatted shipping
  address, items ordered, shipping method paid for.
- Accept tracking back via `createReceiptShipment` — this marks the order
  shipped and emails the buyer with tracking, exactly as if you'd done it in
  the Etsy UI. It also accepts optional shipment details (service level,
  weight, dimensions, label cost, ship date), which Etsy uses for faster
  tracking updates; we send everything we know from the purchased label, and
  fall back to the tracking number alone if Etsy refuses any of it.

So we don't buy the label from Etsy. We buy postage from a **postage API**
(Shippo recommended; EasyPost is equivalent) and push the tracking number back
to Etsy. The carrier barcode (USPS IMpb, etc.) is generated by the postage
provider and is already on the label — we never generate barcodes ourselves.

## Architecture

```
Etsy order paid
      │  order.paid webhook (primary)
      │  + getShopReceipts poll every 3 min (reconciliation / missed events)
      ▼
┌─────────────────────────────────────────────┐
│ Orchestrator service (Raspberry Pi or PC    │
│ physically next to the label printer)       │
│                                             │
│ 1. Fetch receipt from Etsy API              │
│ 2. Skip if already processed (SQLite)       │
│ 3. Validate address (Shippo)                │
│ 4. Pick parcel preset from items ordered    │
│ 5. Buy cheapest matching rate → 4x6 label   │
│ 6. Print label via CUPS (`lp`)              │
│ 7. createReceiptShipment → tracking to Etsy │
│ 8. On any failure: hold order + notify me   │
└─────────────────────────────────────────────┘
      │                          │
      ▼                          ▼
 Label printer            Etsy marks shipped,
 (USB/network)            buyer gets tracking email
```

### Components

| Component | Choice | Why |
|---|---|---|
| Order source | Etsy Open API v3 (`transactions_r/w` scopes, OAuth 2.0) | Only source of truth for orders |
| New-order signal | Poll `getShopReceipts?was_paid=true&was_shipped=false` every ~3 min | No public endpoint to expose from a home Pi; webhook can be added later behind a Cloudflare Tunnel |
| Postage + barcode | Shippo API | Pay-per-label tier, address validation included, native 4x6 PDF/PNG/ZPL output, well-documented |
| Runtime | Single Python service + SQLite, systemd unit on a Raspberry Pi | One box, no cloud hosting, printer is local so printing is a trivial `lp` call |
| Printing | CUPS raw queue (`lp -d label -o media=4x6`) | Rollo/Munbyn/DYMO 4XL all have CUPS drivers; Zebra printers can be sent raw ZPL instead |
| Notifications | Email (or ntfy.sh push) on failure | Orders that can't auto-process must be visible, not silently stuck |

Polling is the recommended v1 signal: a home Pi has no public HTTPS endpoint
for webhooks, and 3-minute latency is irrelevant when packages go out once a
day. The webhook is a clean v2 upgrade (Cloudflare Tunnel makes it feasible
without opening ports).

### Processing rules

- **Idempotency is non-negotiable** — postage costs real money. SQLite keeps a
  row per `receipt_id` with a state machine:
  `new → label_purchased → printed → tracking_posted → done` (or `held`).
  Every step records before it acts; a crash mid-order resumes without
  double-buying.
- **Parcel presets** ✅ — SKUs map to named box presets (`[labels.parcels.<name>]`
  + `[labels.item_parcels]`), or one box for everything (`[labels.parcel]`).
  Multi-item orders spanning presets sum weights and use the largest box by
  volume; an unmapped SKU with no `default_parcel` holds for manual review.
- **Service mapping** — the shipping method the buyer paid for (e.g. Priority
  upgrade) maps to an allowed set of Shippo service levels; buy the cheapest
  rate within that set.
- **Hold, don't guess** — address fails validation, no rate returned, printer
  offline, unmapped item: mark `held`, print nothing, send a notification.
  A `retry <receipt_id>` CLI command re-runs a held order after you fix it.
- **Refunds/cancellations** ✅ — before buying, re-check the receipt status; if
  an order cancels after label purchase, `refund <receipt_id>` asks Shippo for
  the postage back. Deliberately manual: since April 2024 Shippo no longer
  refunds unused USPS labels on its own, the request must land within 90 days,
  and it is rejected once the carrier scans the parcel — so a refund is a
  judgement call about a specific parcel, not something a poller should make.
- **Traceable charges** ✅ — every purchase carries `metadata = "Etsy order
  #<id>"`, which Shippo echoes onto the transaction and shows against the
  charge. Without it the dashboard is a column of near-identical USPS charges,
  and the one question a crashed purchase leaves behind ("was this order
  already charged?") has no answer.

### Money flow

Postage is charged to a card on file with Shippo (or a connected carrier
account) instead of being deducted from your Etsy payment account. Etsy's
commercial-rate discount and Shippo's discount are both USPS Commercial
Pricing, so per-label cost is essentially the same; Shippo's pay-as-you-go
plan adds ~$0.05/label.

## Low-code alternative (worth knowing about)

ShipStation (or Shippo's web app) can sync an Etsy store natively, auto-buy
labels via automation rules, and auto-print through their desktop agent
(ShipStation Connect). Near-zero code, but a monthly subscription,
less control over box/service logic, and you're configuring someone else's
rule engine instead of owning the workflow. This repo exists because we want
the owned-workflow version; if maintenance ever becomes a burden, this is the
fallback.

## Implementation phases

1. **Read-only skeleton** — Etsy OAuth flow (one-time browser consent, refresh
   token stored locally), poll receipts, print *a plain-paper packing slip* to
   prove the loop end-to-end with zero postage risk. ✅ done
2. **Label purchase in Shippo test mode** — test-mode labels (enforced: live
   tokens refused unless `allow_live = true`), parcel presets by SKU, cheapest
   allowed rate, print test labels, verify barcode scans and 4x6 layout on the
   real printer. ✅ done (printer verification pending hardware)
3. **Go live** — real postage, `createReceiptShipment`, failure notifications,
   systemd hardening (restart on failure, boot persistence). ✅ code done —
   tracking posts for live labels only (test labels stop at `label_printed`),
   held orders push to ntfy; flipping live needs only the live token +
   `allow_live = true`.
4. **Nice-to-haves** — packing slip alongside each label, `order.paid` webhook
   via Cloudflare Tunnel, daily summary email, SCAN-form (end-of-day manifest)
   generation.

## Decisions to confirm before building

- **Label printer model** — determines CUPS driver vs raw ZPL (any 4x6
  thermal printer works; the design doesn't change, only the print call).
- **Shippo vs EasyPost** — same architecture either way; Shippo assumed.
- **Where it runs** — assumed Raspberry Pi/PC next to the printer. If you'd
  rather host in the cloud, printing changes to PrintNode (cloud print API
  with a small agent on the machine that has the printer).
- **Auto-buy scope** — v1 auto-buys everything mappable; alternatively start
  with "print a pre-filled approval prompt" mode before trusting it with money.
