# CLAUDE.md — working notes for this repository

Read this before changing anything. README.md is the user-facing manual,
DESIGN.md the original architecture; this file is what a new engineer or AI
session needs to know *cold*: why things are the way they are, the
conventions, the traps, and what was tried and abandoned.

## What this is, and where it runs

A single-shop tool that, for every paid Etsy order: prints a packing/pick
slip, buys a USPS label through the shop's **own Shippo account**, prints it
on a 4x6 thermal printer, and later posts the tracking number to Etsy. It is
**live**: real postage, real buyers.

Production is one Raspberry Pi next to a ZPL thermal printer (raw CUPS queue
named `label`). Two systemd services, both generated by
`systemd/install-service.sh`:

| Unit | Command | Notes |
|---|---|---|
| `etsy-auto-print` | `.venv/bin/etsy-auto-print run` | The poller. Polls every 3 min. |
| `etsy-auto-print-dashboard` | `.venv/bin/etsy-auto-print dashboard` | Flask UI on 127.0.0.1:8765, reached through `ssh -L 8765:localhost:8765`. |

The Pi's user is not `pi`, which is why the unit is generated rather than
edited (see Gotchas). The CLI is not on PATH on the Pi unless the venv is
activated: use `.venv/bin/etsy-auto-print`.

## Development

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev,dashboard]"
.venv/bin/python -m pytest -q
```

- The cloud dev container loses `.venv` on restarts; recreate it with the
  line above.
- One test skips when `pdftoppm` (poppler-utils) is absent. That's expected
  in the container; the Pi has it.
- Python ≥ 3.11 (`tomllib`). Only runtime dependency is `requests`; Flask is
  optional (`[dashboard]`).

## Order state machine

```
new → slip_printed → label_purchased → label_printed → tracking_posted → done
                       (any step)  → held      (digital-only: new → done)
```

- Each step runs at most once; the state is written *before* moving on.
- `label_attempts` is written **before** money moves. A crash between the
  Shippo charge and saving the result leaves an attempt with no label, which
  holds the order ("check the Shippo dashboard") and never re-buys.
  `clear-attempt` resumes after a human checks.
- `held` is never retried automatically. `retry <id>` after fixing the cause.
- Every transition writes an `events` row; `show <id>` prints them. Notes
  carry *why* (e.g. the `tracking_posted` note names the reason Etsy was told
  at that moment).

## Decisions and why

- **Shippo, not Etsy labels.** Etsy's API cannot buy Etsy labels. Postage is
  charged to the shop's Shippo card; tracking is pushed back with
  `createReceiptShipment`.
- **Poll, not webhook.** A home Pi has no public HTTPS endpoint. 3-minute
  latency is irrelevant for once-a-day shipping.
- **Hold, don't guess.** Unmapped SKU, failed address, unknown shipping
  upgrade, international, no rate, printer error → `held` + push. An order
  that sits still is recoverable; one shipped wrong is not.
- **Live tokens refused unless `labels.allow_live = true`.** Default config
  cannot spend money. Test labels never post tracking to Etsy (fake tracking
  must not reach a buyer); test-labelled orders stop at `label_printed`.
- **Tracking is posted on the next business day, not at print time**
  (`labels.mark_shipped`, default `next_business_day`, from
  `mark_shipped_hour` = 8 local). Posting at print time made Etsy email
  "shipped" early and its delivery estimate optimistic. Capped at Etsy's
  ship-by date (`transactions[].expected_ship_date`, earliest line), because
  a *late* mark-shipped hurts seller metrics. Other policies:
  `immediately` (old behaviour) and `carrier_scan` (post when Shippo reports
  TRANSIT/DELIVERED/RETURNED/FAILURE, with the ship-by date as backstop;
  checked at most every 30 min per order; Shippo errors count as "not yet").
- **`ship_date` sent to Etsy is the posting day in local time.** It used to
  be the label's purchase time in UTC, which is "tomorrow" on a US evening.
- **International orders hold after the slip prints.** No customs
  declaration is built. The seller buys that label on Etsy and prints it with
  `print-label` / the dashboard upload. When Etsy marks it shipped,
  `reconcile` notices it left the open-orders list, confirms with
  `get_receipt`, and closes it (404 also closes).
- **Digital-only orders go straight to `done`.** Detected by
  `listing_type` on the transaction (*not* `is_digital`/`type`; see below).
  Anything unrecognised counts as physical.
- **Box choice is a ladder.** `max_items` steps an order up to the smallest
  box that holds it, never smaller than the one outgrown; holds only when no
  configured box fits. One parcel per order.
- **Buy the service the buyer paid for.** Etsy's six standard USPS services
  are mapped; an unrecognised upgrade holds rather than shipping slower.
- **Every Shippo purchase carries `metadata = "Etsy order #<id>"`** so
  charges are traceable. Refunds are a manual command because Shippo stopped
  auto-refunding unused USPS labels (2024), the 90-day window, and the scan
  rule make it a judgement call.
- **Stock alerts fire on transitions** (into low / out), not every sweep.
  `listings_r` is an *optional* scope (`[etsy] optional_scopes`); Etsy did
  not grant it to this shop's provisional app, so the shop can set
  `optional_scopes = []` to stop asking/warning.
- **Order-ready pushes** (`notify.on_order`, default on): silence used to be
  ambiguous between "nothing sold" and "something sold and you missed it".
- **The dashboard binds 127.0.0.1** and refuses a routable bind without a
  password, because it displays tokens that can spend money. It starts even
  when the config is broken (`needs_config=False`) so you can fix the config
  from it.
- **The systemd unit is generated, not edited** (`install-service.sh`), and
  it is a real file, not a symlink into the repo, so `git pull` can neither
  conflict with local edits nor silently change what the service runs.
- **Restart buttons use a narrow sudoers rule** written by the installer:
  exactly `systemctl restart etsy-auto-print` and
  `systemctl restart --no-block etsy-auto-print-dashboard`, validated with
  `visudo -cf`. sudo matches command lines exactly; any change to the
  command the dashboard runs must change the rule too.

## Conventions

- **Git:** work happens on `claude/etsy-shipping-label-automation-dtfnb2`.
  `main` is what the Pi runs. `main` only moves by **fast-forward**, and only
  when the owner says "merge" for that change; approval does not carry over.
  No PRs unless asked.
- **Deploying to the Pi:** `git pull`, then restart **both** services. The
  poller and the dashboard are separate long-lived processes; a pull changes
  files, not running code. `check` and the dashboard both warn when either
  is running older code than the disk.
- **Comments explain why**, usually the incident that motivated the code.
  Match that density. Tests are named as behaviour sentences
  (`test_a_deadline_already_passed_posts_immediately`).
- **User-facing errors name the fix**, ideally as a copy-pasteable command
  (`sudo systemctl restart …`, `retry <id>`, `cancel -a label`).
- **Config validation is strict:** unknown parcel keys, both parcel styles,
  per-SKU box names that don't exist, bad `mark_shipped` values all fail at
  startup with guidance rather than being ignored.
- **Checks never raise**; a broken dependency is a red row, not a 500.
- `test_labels.label_config()` pins `mark_shipped="immediately"` so older
  pipeline tests keep their meaning; ship-day tests opt in explicitly.

## Secrets and buyer data

Never commit: `config.toml`, `config.toml.bak`, `tokens.json`, `orders.db`,
`outbox/`, `label/`, `items.csv`, `*.bak`, `.validate-*` (all in
`.gitignore`). No credential has ever been in history; keep it that way.
`dump-receipt` redacts buyer details unless `--raw`; don't paste raw output
or real label PDFs into third-party sites. Never ask the owner to paste a
Shippo token into chat.

## Gotchas (facts learned the hard way)

**Etsy API**
- `x-api-key` must be `keystring:shared_secret` (since Feb 9 2026).
- Scopes required: `transactions_r transactions_w shops_r` (`shops_r` for the
  `/users/me` shop lookup). `listings_r` is optional and may not be granted.
- Download listings are identified by `listing_type`. `is_digital` and
  `type` were guesses that didn't exist. When unsure of a field name, print
  what Etsy actually sent ("Etsy calls it: …") rather than guessing again.
- The active-listings endpoint excludes sold-out listings, so `listings` and
  stock monitoring use the all-listings call with a fallback.
- **Etsy rewrites `expected_ship_date` once an order ships** to the actual
  ship day. On shipped orders it is not a deadline; `ship-by` reports when
  Etsy was told instead.
- Cancelled orders don't restore listing quantity (decremented at purchase).
- OAuth on the headless Pi: `auth --no-browser` plus
  `ssh -L 8231:localhost:8231`. `auth` never launches a text browser (lynx
  once hijacked the flow with cookie prompts); it only opens a browser when
  a graphical one is available.
- Refresh tokens die after ~90 days idle → rerun `auth`.

**Shippo**
- USPS label purchases need a `ship_from` email.
- Tracking status values (`UNKNOWN`, `PRE_TRANSIT`, `TRANSIT`, `DELIVERED`,
  `RETURNED`, `FAILURE`) are from memory, not verified against live docs
  (docs site was unreachable from the dev proxy). The code fails safe: an
  unknown value is "not scanned yet", and the ship-by date still forces the
  post. Verify with `track <id>` on a real parcel before relying on
  `carrier_scan`.

**Printing**
- A raw (ZPL) CUPS queue *accepts* a PDF, reports a request id, prints
  nothing, and can jam the queue so later jobs stall. Hence `pdf2zpl` and
  the conversion note on every `print-label`.
- PBM P4 from `pdftoppm -mono` maps byte-for-byte to `^GFA` data.
- `lpq` isn't installed on the Pi; use `lpstat -o <queue>`. A jammed queue
  is cleared with `cancel -a label` (and sometimes a printer power-cycle).
  `check` warns at ≥2 queued jobs; one job is normal traffic.

**systemd / sudo / processes**
- `git pull` without a restart leaves old code running while `check` (a
  fresh process) reports the new version. This caused a real order to be
  marked shipped at print time after the next-business-day fix had been
  pulled (2026-09-26). The poller now stores `running_version()` in the
  `meta` table; `check` compares it to the disk.
- The desktop launcher can start its own dashboard, which holds port 8765
  and stops the service from starting. The restart button compares the
  service's MainPID to `os.getpid()` and refuses with an explanation.
- The dashboard restart is deferred (`threading.Timer`) with `--no-block` so
  the "Restarting…" page is delivered before systemd kills the process; a
  failure is recorded and shown on the next page load.
- `sudo -n -l <exact command>` probes permission without running anything.
- Under `sudo`, `$USER` is root; the installer uses `SUDO_USER` and refuses
  to install a root service.

**Config**
- Parcel weight belongs in `[labels.item_weights_oz]`, not in a parcel
  table (`weight_oz` there was once silently ignored; it's now rejected).
- Two `shippo_token` lines is a TOML error: comment one out before
  uncommenting the other.
- Running the CLI outside the project dir: `installed_config_path()` finds
  the installed checkout's `config.toml` and says "Using …" on stderr.

## Tried and abandoned

| Tried | Why it didn't work | Replaced by |
|---|---|---|
| Posting tracking the moment the label printed | Buyer told "shipped" days early; Etsy estimate too optimistic | `mark_shipped` policies |
| Label `created_at` (UTC) as Etsy `ship_date` | Wrong day on US evenings | Posting day, local time |
| Sending Etsy PDFs straight to the raw label queue | Printed nothing, jammed the queue | `pdf2zpl` |
| `lpq` for queue checks | Not installed on the Pi | `lpstat -o` |
| Restart dashboard via redirect | Dead-end page | Self-refreshing "Restarting…" page |
| Documented sudoers rule for the poller only | sudo exact-match silently refused the dashboard restart | Installer writes both exact rules |
| Symlinking / hand-editing the tracked unit file | Dirty tree, `git pull` conflicts, pulls changing the live service | Generated unit file |
| Guessing Etsy field names (`is_digital`, `type`) | Fields don't exist | `listing_type` + "Etsy calls it:" diagnostics |
| Reading `expected_ship_date` as the ship-by on shipped orders | Etsy rewrites it on shipment | `ship-by` reports shipped orders separately |
